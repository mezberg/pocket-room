# Designer flow: live run, 1 Nov 2026

Every result below came from the app's own pipeline and the live models, driven through the real UI in headless
Chrome (`scripts/flow-run.mjs`, `scripts/ui-drive.mjs`): rooms from Kate's Zoopla screenshots via the New room flow
(`/api/rooms/from-photo`), pieces from `/api/pieces` (photo, screenshot), `/api/pieces/from-link` and
`/api/agent/find`, advice and plan picks from the Decisions API, placement and fixes from rules/ + fixes/ + designer/.
No room, piece, finding or fix was written or edited by hand. Raw server log: `flow-server.log` (one line per API
call and per model call). Inputs: `docs/test-inputs/zoopla/`.

## Issues found (reported, not patched in the data)

1. **Find for me can't use move-then-place**: in Kate's flat "an armchair" returns "Nothing we found fits this
   room". The agent filters products by free wall space (`agent/space.mjs`) before the designer sees them, while
   designer/ can clear a spot by moving the side table (an armchair of 0.78 m gets that plan in tests). Fix: let
   the agent keep pieces that fit after moves (ask `/api/plan`), in agent/ (another session's area).
2. **The room from photos varies run to run**: Zoopla A from the same 5 photos had an L-shaped sectional in one
   build and no sofa in the next, so "find a sofa" placed a second sofa instead of offering to replace it (#4).
3. **"Fits" 4 cm from a door**: #4's free spot is 4 cm from the door (the reason now skips warnings, but rules/
   still accepts the spot; doorway depth is checked, not the clearance beside the frame).
4. Place in photo rooms named no wall ("Put it there, where your photos show the room", room/photo/seen.mjs): in
   the designer flow the plan sentence now names the wall; the old sentence lives in room/ (not edited).
